# Mainframe Teil 3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A "Dienste" area with uptime checks, a home-network scanner with an inventory, an internet watcher (outages + speedtest), and two-factor login.

**Architecture:** Three small server modules (checks, scanner, internet), each with its own SQLite tables (schema v4), a timer started in `buildApp` and REST routes under `/api`. TOTP lives in `auth/`. The web gets one new tab "Dienste" with three segments (Dienste · Geräte · Internet) and a 2FA group in Konto & Sicherheit.

**Tech Stack:** Fastify 5, node:sqlite, node:crypto (TOTP), node:net/dns/child_process, React 19, vitest. No new dependencies.

**Spec:** docs/superpowers/specs/2026-11-25-mainframe-ausbau-design.md (sections "Teil 3" and the "Neu (Jonas, 2026-11-25)" items for Zwei-Faktor-Anmeldung and Internet-Wächter).

## Global Constraints

- UI text German, README/CHANGELOG English; commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- No paid services, no registration. Repo is public: no real IPs, names or secrets in code or tests (use 192.168.1.x / 100.64.0.x examples).
- Every `/api` route except auth state/setup/login stays behind the existing auth guard.
- Background work must not block the live stats; Windows commands are slow (cache, run in parallel with limits).
- History tables are pruned after 7 days, like `stats_history`.
- Motion off under "Bewegung reduzieren"; status never by color alone (text + color).
- Factory reset (`/api/system/reset`) also removes the 2FA keys.

## Review Focus

1. A check target that hangs (no answer) must time out (5 s) and count as down, never pile up overlapping checks.
2. The scanner on Windows: `arp -a` output in German locale ("Internetadresse", "Physische Adresse", "dynamisch") must parse; randomized MACs (locally administered bit) are labeled, not given a wrong vendor.
3. 2FA: a wrong or reused code is rejected, codes from ±1 time step are accepted, recovery codes work once; turning 2FA off needs password + code.
4. The internet watcher with no internet: the speedtest fails gracefully ("Kein Internet") and outages are recorded as one outage, not one per probe.
5. Deleting an installed app removes its tile; a custom link with an invalid URL (`javascript:`, `file:`) is rejected.

### Task 3: Network scanner and inventory

**Files:** Create `apps/server/src/network/scanner.ts`, `network/oui.ts`, `network/routes.ts`; Test `apps/server/test/scanner.test.ts`.

**Interfaces:**
- `parseArp(text: string, platform: 'win32' | 'linux'): {ip, mac}[]` — Windows `arp -a` (any locale: lines `  <ip>  <aa-bb-cc-dd-ee-ff>  <type>`), Linux `ip neigh` (`<ip> dev X lladdr <mac> REACHABLE|STALE`); drops broadcast/multicast (`ff-ff-…`, `01-00-5e…`), normalizes MAC to `aa:bb:cc:dd:ee:ff`.
- `isRandomMac(mac): boolean` (second hex digit in 2, 6, A, E).
- `createOui(dataDir, fetchFn)` → `lookup(mac): string | null`; downloads `https://standards-oui.ieee.org/oui/oui.csv` once into `<dataRoot>/oui.csv` on first scan, failures ignored.
- `createScanner({db, events, subnet: () => string[] /* host IPs of the LAN /24 */, readArp, sweep, reverse, oui})` → `scan(): Promise<DeviceInfo[]>`; sweep = TCP connect to port 80 with 400 ms timeout, 64 at once; hostname via `dns.reverse` (1 s timeout). New device → event "Neues Gerät im Netzwerk: …". Only one scan at a time.
- `GET /api/devices` → `DeviceInfo[] {mac, ip, hostname, vendor, randomMac, name, note, known, isNew, firstSeen, lastSeen, online}`; `POST /api/devices/scan`; `PATCH /api/devices/:mac {name?, note?, known?}`.
- Prefs: `scanMinutes: 60 | 0 | 15 | 360` (0 = only by button).

- [ ] Tests: `parseArp` with a German Windows sample and a Linux sample; random MAC; scan with fakes creates devices, marks new once, keeps names; concurrent scan calls share one run; PATCH validates (name ≤ 40, note ≤ 200).
- [ ] Red → implement → green. Commit `feat: netzwerk-scanner mit geräte-inventar`.

### Task 4: Internet watcher

**Files:** Create `apps/server/src/internet/watcher.ts`, `internet/routes.ts`; Test `apps/server/test/internet.test.ts`.

**Interfaces:**
- `probe(): {ok, ms}` — TCP connect to `1.1.1.1:443`, then `8.8.8.8:53` if the first fails (2 s each).
- `speedtest(fetchFn)`: ping = time of a 0-byte request; download `https://speed.cloudflare.com/__down?bytes=25000000`; upload 5 MB POST to `https://speed.cloudflare.com/__up`; Mbit/s rounded to 0.1. Throws `MainframeError('offline', 'Kein Internet, Test nicht möglich.')`.
- `outages(probes): {from, to, minutes}[]` — runs of ≥ 2 failed probes.
- Watcher: probe every 60 s, speedtest every `speedtestHours` (`24 | 0 | 6`, default 24); events "Internet weg" / "Internet wieder da (nach N Min.)".
- `GET /api/internet?minutes=1440|10080` → `{online, lastProbe, outages, speedtests, running}`; `POST /api/internet/speedtest` (one at a time, 409 if running).

- [ ] Tests: `outages` merges consecutive failures; single failure is no outage; speedtest with fake fetch computes Mbit/s, offline error; route returns outages for the range.
- [ ] Red → implement → green. Commit `feat: internet-wächter mit ausfällen und speedtest`.

### Task 5: Two-factor login (TOTP)

**Files:** Create `apps/server/src/auth/totp.ts`; Modify `auth/routes.ts`, `system/admin-routes.ts` (reset); Test `apps/server/test/totp.test.ts`.

**Interfaces:**
- `base32Encode/Decode`, `totp(secret: Buffer, at: number): string` (RFC 6238, SHA-1, 30 s, 6 digits), `verifyTotp(secret, code, at, lastStep): number | null` (±1 step, returns matched step, rejects step ≤ lastStep).
- Settings keys: `totp_secret`, `totp_pending`, `totp_last_step`, `totp_recovery` (JSON array of scrypt hashes via existing `hashPassword`).
- `GET /api/auth/2fa` → `{enabled}`; `POST /api/auth/2fa/setup {password}` → `{secret, uri}` (`otpauth://totp/Mainframe:<user>?secret=…&issuer=Mainframe`); `POST /api/auth/2fa/enable {code}` → `{recoveryCodes: string[10]}` (format `xxxx-xxxx`); `POST /api/auth/2fa/disable {password, code}` (code may be a recovery code).
- Login: when enabled and password+user ok but `code` missing → 401 `code_required` "Bitte den Code aus deiner Authenticator-App eingeben."; wrong code → 401 `wrong_code`; recovery code is consumed.
- Reset deletes all `totp_*` keys.

- [ ] Tests: RFC 6238 test vector (secret `12345678901234567890`, t=59 → `287082`); ±1 step; replay rejected; setup→enable→login needs code; recovery code works once; disable needs both; reset clears 2FA.
- [ ] Red → implement → green. Commit `feat: zwei-faktor-anmeldung mit authenticator-app`.
