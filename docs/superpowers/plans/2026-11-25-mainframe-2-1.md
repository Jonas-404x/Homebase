# Mainframe Teil 2.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Jonas' feedback after Teil 2: a clean overview, a one-minute mini chart, detail pages with long history (up to 7 days) including temperature and process lists, full-disk and temperature warnings, Android-style phone effects, a Minecraft "Kommt bald" tab, more catalog apps and Tailscale access.

**Architecture:** The history moves from memory into SQLite (table `stats_history`, a 10 s sample, kept 7 days, aggregated into buckets by SQL). New read-only endpoints for details and processes. In the web app, a `/details/:metric` page with a large SVG chart; the cards link there.

**Tech Stack:** as Teil 2 (Fastify 5, node:sqlite, systeminformation, React 19, vitest).

**Spec:** `docs/superpowers/specs/2026-11-25-mainframe-ausbau-design.md`, section "Teil 2.1".

## Global Constraints

- All UI text is German; the README and CHANGELOG are English.
- Contrast is ≥ 4.5:1 (`node scripts/contrast.mjs`). Touch targets on the phone are ≥ 44 px. Every animation is off under `prefers-reduced-motion`.
- No placeholders, except the Minecraft tab (Jonas' wish).
- No secrets in the repo. Tailscale sign-in is done by Jonas.

## Review Focus

1. A history request for 7 days on a fresh database (no rows) returns `[]`, and the detail chart shows the loading or "Noch keine Daten" state.
2. Restarting Mainframe keeps the history: the rows are in SQLite.
3. When the temperature is null (Windows), the detail page explains why, without crashing or drawing an empty graph.
4. A disk warning is written once per threshold crossing, not on every sample.
5. The process list on Windows is slow (`si.processes()` takes about 1–3 s). It is cached and never blocks the live stats.

### Task 1: Persistent history, details, processes, warnings (server)

- DB v3 adds the table `stats_history(at INTEGER PRIMARY KEY, cpu REAL, memory REAL, rx INTEGER, tx INTEGER, temp REAL)`. The migrations run in a transaction.
- `Db.addStatsPoint`, `Db.queryStats(from, to, points)` (AVG per bucket), `Db.pruneStats(before)`.
- `HistoryPoint` gets `temp: number | null`.
- `GET /api/system/history?minutes=15|60|360|1440|4320|10080&points=2..500` (default 120).
- `GET /api/system/details` returns per-core load, clock speed, the memory breakdown, swap, network adapters and the core temperatures.
- `GET /api/system/processes?sort=cpu|memory` returns the top 15 with a 3 s cache.
- Prefs:
  - `historyMinutes` adds the value 1, and its default becomes 1.
  - New `detailMinutes`, one of 15|60|360|1440|4320|10080, default 1440.
- The sampler writes an event when a disk goes past `thresholds.disk` or the temperature goes past `thresholds.temperature`. It writes it once, and again only after the value has dropped below the threshold − 2.
- Tests: persistence across reopening the DB, bucketing, the allowed minutes, the details/processes shape, a warning written once.

### Task 2: Overview cleanup and detail pages (web)

- The AdGuard widget moves to its own "Dienste" section under the system cards. It is no longer part of the card grid. The `adguard` entry in prefs.cards still controls whether it is shown.
- Mini charts: `historyMinutes === 1` shows only the live points of the last 60 s. Otherwise it shows the server history as before.
- A disk warning notice at the top when a disk is ≥ its threshold.
- The cards for CPU, memory, network and temperature link to `/details/:metric`, with the whole card clickable and a visible "Details ›" link.
- The page `/details/:metric`:
  - Back link, current value, range switch (default `prefs.detailMinutes`), a large chart (axes, time labels, a touch/hover readout).
  - Min/Ø/Max.
  - Extras:
    - CPU: per-core load and processes by CPU.
    - Memory: breakdown and processes by RAM.
    - Network: download and upload lines, adapters.
    - Temperature: cores, or an explanation when there is none.
- Settings → Übersicht: "Verlauf" gets the 1 Min. option; new row "Detailansicht".

### Task 3: Phone effects, Minecraft tab, catalog apps, Tailscale display

- Nav: a 4th item "Minecraft" leads to the `/minecraft` page "Kommt bald".
  - On the phone, a pill indicator behind the active icon.
  - Ripple on tap for nav, buttons, list items and clickable cards.
  - Page fade-through on the phone, and the settings pane slides in from the right.
- Catalog: uptime-kuma, jellyfin, navidrome, vaultwarden, ntfy, home-assistant, each with an icon and sensible ports. A test checks that the catalog loads and every icon is known.
- Settings → Netzwerk: when there is a Tailscale address (100.64.0.0/10), the "Fernzugriff" row is active and shows its own QR code.
